### 1.2 外壳（`E:\dev\klecks-desktop\main.js`）当前职责

- 起一个只监听 `127.0.0.1` 的静态服务器指向 `dist/`，用 `http://127.0.0.1:<随机端口>` 加载 —— **必须**，否则 ES 模块被 CORS 拦、ServiceWorker 与 `showSaveFilePicker` 因非安全上下文不可用。
- `BrowserWindow` 1440×900，无菜单栏（`setApplicationMenu(null)` + `setMenuBarVisibility(false)` + `autoHideMenuBar`）。
- 快捷键由 `before-input-event` 兜住：F5 / Ctrl+R / Ctrl+Shift+R / F12 / F11。
- `will-prevent-unload` 接管：页面有未保存改动时弹原生确认框，否则窗口关不掉。
- 外链交给系统浏览器（`setWindowOpenHandler`）。
- `--smoke` 自检模式：轮询等渲染完成 → 取像素指纹 → CDP 真输入画一笔 → 像素差 → 截图 → `closeTest` → 写 `smoke-result.json` → 退出。

### 1.3 已知缺陷 / 待改（编号见 §6）

- D1 无磁盘自动保存（页面自带的 IndexedDB 恢复只在应用内，profile 一清就没）
- D2 不能双击图片打开、无文件关联、无"打开方式"、无单实例
- D3 未启用 GPU 光栅化等开关，大画布偏卡
- D4 上游缺全局对称、图层级 alpha 锁等（见 §3 补丁清单）
- D5 `capturePage()` 截图不含菜单栏/标题栏（自检时不能靠截图判断窗口装饰）

## 二、数据流与关键约束

```
Kleks.exe (Electron)
 ├─ main 进程 main.js
 │   ├─ http server 127.0.0.1:随机端口 ──> dist/（index.html + 77 个静态文件）
 │   ├─ BrowserWindow ──loadURL──> http://127.0.0.1:<port>/index.html
 │   └─ 页面控制权：webContents.executeJavaScript / debugger(CDP) / will-download / will-prevent-unload
 └─ renderer（上游 Kleks 原样跑）
     ├─ 画布数据在内存 + IndexedDB（库名 Klecks，ProjectStore/RecoveryStore/ImageDataStore）
     ├─ 保存：saveAs() → 默认 `<a download>`；勾了"Show save dialog"才走 showSaveFilePicker
     └─ 导入：window 上的 dragenter/drop（KlImageDropper，见 kl-image-dropper.ts）
```

**硬性不变量（不得违反）**

1. `file://` 加载会白屏 —— 永远不要改成 `loadFile`。
2. 页面保持 `contextIsolation: true` / `nodeIntegration: false`；外壳与页面之间只用 `executeJavaScript` 与本地 HTTP，不引入 preload+IPC 的隐式通道（除非本书更新）。
3. 不修改上游 `dist` 产物本身；上游改动一律改源码 `E:\dev\klecks\src` 后重新 `npm run build` 覆盖。
4. 自检必须走真实输入（CDP `Input.dispatchMouseEvent`，带 `buttons`），`sendInputEvent` 的 mouseMove 不带按键状态，会假阴/假阳。
5. 品牌：产物一律叫 **Kleks**，不得使用 Kleki 名称/标识对外提供带品牌的在线服务。

## 三、上游补丁清单（本项目唯一允许改动上游的范围）

| 补丁 | 目的 | 涉及文件 | 状态 |
| --- | --- | --- | --- |
| P1 全局对称绘制 | 所有画笔支持左右 / 上下 / 四向镜像 | **新增** `klecks/brushes/symmetry-brush.ts`；`brushes-ui/` 7 个文件各加一层包装；`ui/tool-tabs/settings-ui.ts` 加开关 | ✅ 已完成（2026-09-27，deps: 0，ver: 通过） |
| P2 图层级 Alpha 锁定 | 图层属性级"锁定透明像素" | `kl-types.ts`、`layers-ui.ts`、笔刷落笔合成 | ⏳ 未做（见 D9 说明） |
| P3 视口可见区渲染优化 | 大画布/多图层不再每帧重采样整张画布 | `ui/project-viewport/project-viewport.ts`（新增 `computeVisibleProjectRect` + drawLayer 只画可见源矩形） | ✅ 已完成（2026-09-27，ver: 自检通过 + 缩放截图肉眼确认无缺块） |

### P3 实现要点

- 原逻辑（上游）：每帧每层 `ctx.drawImage(layer.image, 0, 0)` —— 把**整张 document 画布**交给浏览器缩放，成本 ≈ 图层数 × 整张画布像素数（混合模式更贵）。
- 现在：用 `renderedMat` 的逆矩阵把视口四角映回 document 空间取外接盒（+ 按缩放的余量），只画这块源矩形：`drawImage(img, sx,sy,sw,sh, sx,sy,sw,sh)`。混合模式是逐像素运算，少算看不见的部分**结果一致**。
- 带自身 transform 的动态图层（滤镜/FFD 预览）仍走整张绘制，不改。
- **收益条件**：只有"可见面积 < 整张画布"时才省，即**放大作画**时；按面积约 1/缩放²。缩到 fit 看全图时整张本来就可见 → 无收益（成本天然如此）。
- 诊断：渲染时把 `window.__kleksVisibleRect = {visible, document, layers}` 暴露出来，方便量化。

### P1 实现要点（给未来的自己）

- 不改任何笔刷内部实现：`createSymmetryBrush(brush, factory, { mode })` 用 Proxy 包住笔刷实例。
  - 非落笔方法（`set*`）→ 记录进 callLog + 转发原笔刷 + 同步已有镜像实例；
  - 镜像笔刷懒创建，创建时重放 callLog，保证参数与原笔刷一致；
  - 画布尺寸从 `setContext(ctx)` 的 `ctx.canvas` 里取，镜像公式 `x' = width-1-x`、`y' = height-1-y`。
- **三种模式必须按笔刷特性选**（这是修"交界处乱闪"的关键）：
  | 模式 | 适用笔刷 | 原因 |
  | --- | --- | --- |
  | `live` | 铅笔 / 素描 / 像素 / 橡皮 | 每步只往画布叠像素，可以两个实例逐帧同步落笔（实时镜像预览） |
  | `native` | **水彩 blend、晕染 smudge、异形图形 chemy** | 前两者"持有整层缓存 + 每帧 putImageData 整块覆盖写回"，两个实例同时跑必然互相覆盖 → 交界处闪烁；且 `putImageData` **忽略画布变换**，没法像 chemy 那样在渲染层镜像。所以给这两支笔刷**内部**加了 `setXSymmetry/setYSymmetry`：在**同一实例、同一份缓存**里把镜像点追加进同一次计算，每帧只写回一次。chemy 本来就有这套 API，直接复用 |
  | `sequential` | （当前未使用，保留作后备） | 落笔期间只记录轨迹、抬笔后一次性回放镜像笔画。用于"整层重合成"型但**还没加内置对称**的笔刷 |
- 水彩：`flushDrawBuffer()` 内镜像 `drawBuffer` 条目（含索引框 x1/x2 交换）并扩展 `redrawBounds`；晕染：`goLine()` 内镜像 `TSmudgeParams`（迁移矩形按左边界镜像 `w - size.w - x`、笔刷中心按像素中心镜像 `w-1-x`）并用 `getSmudgeBounds` 扩展重绘范围 —— 否则镜像区域不会被写回，也不会进历史。
- **收益**：全程单实例单写回 → 实时镜像 + 结构上不可能闪烁；历史只推一条 → `native` 模式**一次撤销**即可（`live` 模式仍需两次，见 D8）。
- 开关：设置面板两个 Checkbox（复用 Chemy 笔刷已有的 `brush-chemy-mirror-x/y` 翻译键），值存 `localStorage: kl-symmetry-horizontal / kl-symmetry-vertical`。
- 取舍（D8）：`live/sequential` 模式下镜像笔刷会往同一份 `KlHistory` 推自己的条目 → **一次对称笔画需要撤销两次**（`native` 模式没有这个问题）。


> 每个补丁完成后，必须在本表更新状态，并在 §7 变更日志留一条记录（日期 + 原因 + 影响面）。
